トークンの作り方

表示・書き換え・並べ替え・PR のマージのすべてに使える 1 本を作ります。

  1. GitHub の Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
  2. Resource owner: aiyzkn
  3. Repository access: Only select repositories → loop-control と、PR をマージしたい作業対象のリポジトリ（タスクの成果物に PR が載るもの）
  4. Repository permissions:
    • Contents: Read and write … タスクの表示と、書き換え・並べ替え（1 回の操作 = 1 コミット）。PR のマージにも要る
    • Pull requests: Read and write … PR の状態を読み、マージする
    • Commit statuses: Read-only … マージの前に、コミットの状態（commit status）で検査の結果を見る
    • Metadata: Read-only は自動で付く

    fine-grained のトークンには Checks の権限がありません（GitHub の制限。Actions の権限でも代わりになりません）。そのため、GitHub Actions などの check run の結果は読めず、commit status を使わない検査は「検査なし（または読めない）」と出ます。マージの前に、PR の画面で検査を確かめてください。

  5. Organization permissions: Members: Read-only（組織への所属を確かめるため）
  6. 有効期限は短めにする。組織の設定で承認が要る場合は、管理者の承認を待つ

見るだけの端末・人には、Contents を Read-only にし、Pull requests を付けないトークンを使ってください（「送る」「マージする」は 403 で断られます）。

トークンは、このブラウザの中（既定はタブを閉じるまで）にだけ置き、api.github.com にだけ送ります。書き込みは、確認の画面で「送る」「マージする」を押したときだけです。書き込みのできるトークンなので、「このブラウザに覚えさせる」は自分専用の端末だけで使ってください。

指令リポジトリ のタスクと PC の状況を表示します。トークンに書き込みの権限があれば、タスクの書き換え・並べ替え・PR のマージ・依頼の登録もできます（送る前に差分を見せます）。組織 のメンバーだけが使えます。
