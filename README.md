# loop-control-dashboard

ループエンジニアリングの指令リポジトリ [`aiyzkn/loop-control`](https://github.com/aiyzkn/loop-control)（非公開）のタスクと PC の状況を表示し、トークンに書き込みの権限があれば、タスクの書き換え・並べ替え・PR のマージ・依頼の登録もできる静的なページです。GitHub Pages で公開します。

- このリポジトリ（公開）には、**データを置きません**。画面のコードだけです
- 画面は、利用者の GitHub の fine-grained の個人用トークンで、ブラウザから GitHub の API（`api.github.com`）を読みます。トークンで非公開の `loop-control` を読めない人には、何も表示されません
- 組織 `aiyzkn` のメンバーであることも確かめます（画面の中の確認です。実際に読めるかどうかは、トークンの権限で決まります）
- 書き込みは、トークンに `Contents: Read and write` があるときだけ、確認の画面（差分）で「送る」を押したときに行います（下の「書き込み」）。PC のスリープ・再開の指示はできません

## 表示するもの

| 区分 | 中身 | 出どころ |
|---|---|---|
| まとめ | 全体の 3 色信号、アナログメーター（完了の割合・手が動いている割合・PC の最後の確認）、作業中・判断待ち・止まっている・着手待ち・受付の未整理・緊急の件数 | `projects/*/tasks/*.md`・`projects/*/archive/*.md`（数だけ）・`state/pcs/*.json`・`inbox.md` |
| グラフ | 案件ごとの状態の積み上げ、直近 14 日の起票と完了（タスク ID の日付で数える） | タスクの一覧（git の tree） |
| PC の状況 | 信号・最後の確認・判断（起こした / 見送り）と理由・セッションの数（動いている / 入力待ち / 上限 / 指示なし）・次の復帰・次の週次の起動 | `state/pcs/<エージェントの ID>.json`（自動起動 `kick.ps1` が書く） |
| 上限の帯（PC の状況の下） | 直近 7 日と明日の、上限の窓（週・5 時間）の帯。行は `roster.md` の「AI のアカウント」ごと（未記入なら PC ごと）。濃い帯は上限に当たった窓、枠は今の窓。窓の始まりは解除時刻から窓の長さを引いた推定。背景の灰色は夜（東京の日の入り〜日の出。ブラウザで計算） | `state/pcs/<エージェントの ID>.json` の `limits`（`kick.ps1` がセッションの記録から書く） |
| タスク | 信号・状態・優先・案件・件名・段階・担当・PR / MR・現在地（進行中・次の一手） | タスクファイルの先頭と「成果物」「現在地」 |
| 未マージの PR | 案件の「リポジトリ」の表にある GitHub のリポジトリの、開いている PR（更新の新しい順。下書きの印・作成者・ブランチ・関係するタスク）。「状態・マージ」からマージ（関係するタスクがあれば、そのログに記録）。右隣の「開く」「URL」で、PR のページを開く・URL を写す（別の端末・別のアカウントで開くため）。トークンの持ち主のアカウントが書き込めないリポジトリには印を付け、マージを押せないようにする（fine-grained のトークンは、持ち主の権限を超えられない）。節を開いたときだけ、リポジトリごとに API を 1 回（開いている PR があれば、権限を読むためにもう 1 回） | `projects/*/project.md` の「リポジトリ」の表、GitHub の `GET /repos/{o}/{r}/pulls` |
| 案件とリポジトリ | 案件ごとの件数・完了の数・リポジトリ（本流のブランチ・PR / MR の一覧）・アカウント | `projects/*/project.md` の「リポジトリ」の表 |
| 受付 | 未整理の依頼、手が空いた時に実行するタスクの定義 | `inbox.md` |
| ビジュアル（既定で畳む） | カード（案件ごとの進行中・待ちの数・完了・高以上・状態の帯）、マトリックス（案件 × 状態・優先度。セルの濃さ = 件数）、ツリーマップ（案件の大きさ = タスクの数。中は状態と完了）、ガントチャート（起票から今・完了まで。期間は 今日・3 日・7 日・14 日（既定）・30 日 から選ぶ（今日は 3 時間ごとの目盛り）。最後の印の点。最初は新しい 20 行だけ、「すべて表示」で残り。期間と表示の数はブラウザに覚える）、リボンチャート（直近 14 日の起票の累計。日ごとに多い案件が上。上位 7 件 + その他）、GitHub の芝（組織 `aiyzkn` = メンバーの組織内の貢献の合計と、メンバーそれぞれのすべての貢献。直近 1 年） | タスクの一覧と `projects/*/archive/*.md`（数だけ。ガントチャートの完了は「完了したタスクも読む」を押したときだけ、直近のもの（ID の日付が窓の始まりより期間ぶん前以降）を最大 40 件読む。期間を延ばすと、足りない分だけを読む）。芝は `GET /orgs/aiyzkn/members` と GraphQL（`contributionsCollection`）を、ビジュアルの節を開いたときだけ 3 回 |

### 即時実行（いま実行・このタスクを実行）

- 「PC」の表の「いま実行」、またはタスクの書き換えの画面の「このタスクを実行」を押すと、指令リポジトリに `state/kick/<エージェントの ID>.json`（`requestedAt`・`by`・`task`）を 1 コミットで書きます
- PC は 3 分ごと（キットの `kick.pollMinutes`）に `kick-poll.ps1` で見に行き、自分宛ての依頼があれば `kick.ps1 -Trigger now` でセッションを起こします（`task` があれば、そのタスクを先に再開・着手させます）。起きるまで最大で 3 分と少しです
- ほかのセッションが手を動かしている・上限の解除待ちのときは、依頼を残して空くのを待ちます。起こした・起こせない理由が続くときは、PC が依頼を消します。結果は「PC」の表の「即時実行」に出ます（PC の状況の `lastRequest`）
- PC に HTTP の口は開けません（ほかのサイトから叩かれうるため。このページの通信先は api.github.com だけのまま）
- PC の側の対応は aiyzkn/auto-loop-engineering の `kick-poll.ps1`（`install.ps1 -NoCopy -EnableKick` で、見に行くタスク `AutoLoopKickPoll` も登録されます）

### 信号の意味

| 対象 | 赤 | 黄 | 緑 | 消灯 |
|---|---|---|---|---|
| タスク | 止まっている（`blocked`） | 判断待ち（`waiting`）・マージ待ち（`review`）・着手待ち（`ready`。日数によらず）・作業中で印が 24 時間超 | 作業中 | 下書き |

### 状態の切り替え（利用者の番とエージェントの番）

状態は「いま誰の番か」で分かれます。利用者の番は、判断待ち（`waiting`）とマージ待ち（`review`。PR / MR を出したタスク）です。

- 書き換えの画面で、判断待ち・マージ待ちのタスクの質問に答え、未回答の質問が無くなると、同じコミットで作業中（`doing`）に戻します（エージェントの番。担当は保ちます）。状態を自分で選んだときは、その状態にします
- PR をこのページでマージすると、タスクのログに記録し、マージ待ち・判断待ちなら作業中（`doing`）に戻します。残りの PR の確かめと完了（`archive/` への移動）は、エージェントが行います
- マージ待ちのタスクも、並べ替えの画面と一覧に出ます（マージされて完了になるまで残ります）
| PC | 判断が失敗・最後の確認から 3 時間超 | 見送り・上限で止まったセッションがある | それ以外 | — |
| 全体 | 赤が 1 つでもある | 黄がある | 緑がある | どれも無い |

### リンク

案件（`project.md`）・タスク・Markdown（`inbox.md`・`roster.md`・`policy.md`・`AGENTS.md`）・PC の JSON は、指令リポジトリの GitHub の画面へ。エージェントの ID は `roster.md` のその行へ。リポジトリ・ブランチ・PR / MR の一覧・アカウントは、`project.md` の表のホストとパスから組み立てます。タスクの PR / MR は、「成果物」「現在地」に書かれた URL と、案件のリポジトリが 1 つに決まるときの `#番号`（GitHub）・`!番号`（GitLab）から拾います。外部へのリンクは `https://github.com/` と `https://gitlab.com/` だけで、使えない文字を含むパスにはリンクを張りません。

読み方は、auto-loop スキル（[aiyzkn/auto-loop-engineering](https://github.com/aiyzkn/auto-loop-engineering) の `skills/auto-loop`）の決まりに合わせています。受付の数え方は `Get-InboxSummary` と同じです。

## 書き込み

| 操作 | 書き換えるもの | 画面 |
|---|---|---|
| 書き換え | タスクの先頭の `priority`・`status`・`stage`・`assignee`、「利用者への質問と回答」の `回答:`（日付を付けて書く）、ログのメモ | タスクの表の「書き換える」「回答する（未回答の数）」 |
| PR のマージ | 作業対象のリポジトリの PR（GitHub だけ）。マージしたら、タスクのログに 1 行 | タスクの表の PR の横の「状態・マージ」 |
| 並べ替え | 先頭の `priority` と `order`（任意の数。小さいほど先。無いものは同じ優先度の後ろ） | 「並べ替え」の優先度ごとの列。ドラッグ＆ドロップ、カードのボタン、Alt + 矢印キー（上下 = 順、左右 = 優先度） |
| 依頼の登録 | 受付（`inbox.md`）の末尾に 1 件を足す、または `projects/<案件>/tasks/<ID>.md` を直接作る（書く先を選ぶ。既定は受付） | 上の帯の「＋ 依頼を登録」（ダイアログ。閉じても入力は残り、送れたら空になる） |

- **画面の並び。** 上の帯（スクロールしても見える）に「表示」（自動 = OS に合わせる / ライト / ダーク / コックピット = ロボット SF アニメの操縦席の計器風の暗い表示。このブラウザに覚えさせる）「読み直す」「＋ 依頼を登録」「トークン」。その下に、まとめ → 並べ替え（真上にも「読み直す」）→ タスク・PC の状況・グラフ・案件とリポジトリ・受付（折りたためる。開閉はこのブラウザに覚えさせる）。トークンの入力欄と作り方は「トークン」の中で、表示の後は畳む
- **書いた後は、全体を読み直しません。** 書いたファイルだけを手元の表示に反映します（API は書き込みの 5 回と、新しい tree の 1 回）。ほかの人・エージェントの変更は「読み直す」で取り込みます
- **並べ替えの「確認を省いてすぐ送る」**（このブラウザに覚えさせる。既定は確認あり）: 差分の画面を出さず、先に画面の並びを動かしてから送ります。送れなかったら（競合など）並びを元に戻し、理由を上の帯に出します

- **1 回の操作 = 1 コミット。** Git Data API で、読んだ時点のコミットの上に tree → commit を作り、ブランチを fast-forward でだけ進めます（`force: false`）。コミットのメッセージは `[dashboard:<GitHub のログイン>] <操作> <タスク ID>`
- **上書きしません。** 読んだ後に、書き換えるファイルがほかで変わっていたら送りません。送る間にほかの push が入ったら（fast-forward にならない）、作ったコミットは捨てます。どちらも「読み直す」から、やり直します。書き換えないファイル（PC の状況など）だけが変わっていたときは、最新の上に積みます
- 書き換えたタスクは、先頭の `updated` を書き、末尾の「## ログ」に 1 行（`- <時刻> [dashboard:<ログイン>] <出来事>`）を足します（指令リポジトリの `AGENTS.md` の形）
- 並べ替えは、動かしたタスクの `order` を前後の間の値 1 つで済ませます。間が無い・`order` の無いタスクの間に置いたときは、その列を 10 刻みで振り直します（変わるタスクを、まとめて 1 コミット）
- `status` を `done`・`dropped` にしても、`archive/` への移動と担当の解放はしません（エージェントの `finish` で行います）。`urgent` に上げてよいのは利用者だけ（`AGENTS.md` 7.1）なので、このページを使う人が判断します
- 並びの `order` は、auto-loop スキルの `status.ps1`・`kick.ps1` の並べ方に入れる変更（aiyzkn/auto-loop-engineering）と合わせて使います。スクリプトが `order` を知らない間は、ダッシュボードの中だけの並びです
- PR のマージは、PR の状態（開いているか・下書きか・マージできるか・ブランチの保護）と検査（check runs・commit status）を読んで見せ、問題があれば「マージする」を押せないようにします。マージは、見たときの head のコミットを付けて送るので、見た後に push が入っていたら GitHub が断ります（409）。方法は merge / squash / rebase から選びます。マージの後の `finish`（タスクの完了・片付け）はしません。エージェントが再開するときに確かめます
- PR のマージには、トークンの対象リポジトリに作業対象のリポジトリも入れ、`Contents: Read and write` と `Pull requests: Read and write` を付けます（検査を見るには `Commit statuses: Read-only` も。fine-grained のトークンには Checks の権限が無いので、check run の結果は読めず、commit status の無い検査は「検査なし（または読めない）」と出ます）。GitLab の MR は、トークンが別なので対象外です
- 依頼の登録で受付を選ぶと、`inbox.md` の書き方（`## <案件>: <件名>`、`段階:`・`担当:`・`優先:`、本文）で末尾（目印 `<!-- ここから下に追記 -->` の下）に足します。タスクにするのはエージェント（`/auto-loop intake`、自動起動の `next`）です。案件に「新規」も選べます（本文にリポジトリの場所を書く）
- タスクファイルを直接作るときは、指令リポジトリのひな形 `templates/task.md` を読んで、auto-loop スキルの `new-task.ps1` と同じに埋めます（`status: ready`、`source: direct`、ID は `<今日の日付 8 桁>-<短い名前>`。同じ案件の `tasks/`・`archive/` に同じ名前があれば `-2`、`-3`…）。本文は「依頼（原文）」に入ります
- 本文の行頭の `#` とコードの囲み（```）は、`\` を付けて書きます（「## ログ」などの見出しや、受付の件の数え方を崩さないため）
- 書き込みの権限は、リポジトリの情報（`permissions.push`）で見分けます。fine-grained のトークンの権限そのものは、ここに出ないので、`Contents: Read-only` のトークンでは「送る」で 403 になります

## 使い方

1. GitHub で fine-grained の個人用トークンを作る（Settings → Developer settings → Personal access tokens → Fine-grained tokens）。表示・書き換え・並べ替え・PR のマージのすべてに使える 1 本にする
   - Resource owner: `aiyzkn`
   - Repository access: Only select repositories → `loop-control` と、PR をマージしたい作業対象のリポジトリ
   - Repository permissions:
     - **Contents: Read and write** … タスクの表示と、書き換え・並べ替え。PR のマージにも要る
     - **Pull requests: Read and write** … PR の状態を読み、マージする
     - **Commit statuses: Read-only** … マージの前に、コミットの状態（commit status）で検査の結果を見る
     - fine-grained のトークンには Checks の権限が無い（GitHub の制限。Actions の権限でも代わりにならない）。GitHub Actions などの check run の結果は読めず、commit status を使わない検査は「検査なし（または読めない）」と出る。マージの前に PR の画面で確かめる
     - Metadata: Read-only は自動で付く
   - Organization permissions: **Members: Read-only**（組織への所属を確かめるため）
   - 有効期限は短めに。組織の設定で承認が要る場合は、管理者の承認を待つ
   - 見るだけの端末・人には、Contents を **Read-only** にし、Pull requests を付けないトークンを使う（「送る」「マージする」は 403 で断られる）
2. 公開したページを開き、トークンを入れて「表示する」
3. トークンは、既定ではタブを閉じるまでブラウザの中（`sessionStorage`）にだけ置きます。「このブラウザに覚えさせる」を選ぶと `localStorage` に置きます（共有の PC では使わない）。「トークンを消す」で消えます

## 安全のための作り

- `Content-Security-Policy` で、通信先を `https://api.github.com` だけに、スクリプトをこのサイトのものだけに絞っています。外部のライブラリ・解析のスクリプトは使いません
- 表示はすべて `textContent` で入れ、タスクファイルの中身を HTML として解釈しません。リンクの `href` は、決まったホスト（`github.com`・`gitlab.com`）の URL を組み立てて張ります。メーター・グラフは、外部のライブラリを使わず SVG で描きます
- 書き込みの API（`git/trees`・`git/commits`・`git/refs` の作成・更新）は、確認の画面で「送る」を押したときだけ呼びます。見るだけの人は、トークンに読み取りの権限だけを付けてください。書き込む値は 1 行にし（改行・制御文字は空白に）、先頭・質問の行の形を崩さないようにしています

## 開発

依存はありません。読み取りの関数（`parse.js`）・書き換えの関数（`edit.js`）・ビジュアルの計算（`viz.js`。ツリーマップの配置など）の試験:

```
node --test test/
```

手元で開くときは、ファイルを直接開く（`file://`）とモジュールが読めないので、簡単なサーバーを使います（例 `npx serve .`、`python -m http.server`）。
